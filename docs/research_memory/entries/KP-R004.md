## 질문

IBM Fez의 고정 mapping에서 η3=0인 κ-profile이 n에 따라 어떻게 관찰되며 다른 η3·날짜의 묶음과 어떻게 비교되는가? 현재 README의 Fig.5/6/8 선택과 코드에서 재구성한 질문이다.

## 이유

현재 저장소는 시뮬레이션 진단을 QPU에서 비교하고 acquisition time을 바꾼 반복을 분석하도록 구성돼 있다. 이 특정 wrapper를 고른 동시대 의사결정 일지는 보존돼 있지 않다.

## 시도·변경

현재 README가 Day 1에 지정한 η3=0, run=6을 선택해 n=2…7의 signal/control 측정 결과를 연결한다. 이 run 번호는 R8 subrun label 및 Git commit과 서로 다른 식별자다.

## 조건

- 보존된 마지막-R8 metadata 날짜: UTC 2026-01-02, 한국시간 2026-01-03. 누적 histogram에 기여한 모든 subrun 시각을 이 최종 metadata로 대체하지 않는다.
- η3=0, outer wrapper run=6; inner run은 문자열 "6"이다. n=2…7, IBM Fez, model bit_order=lsb.
- physical qubits는 \[3,16,2,4,23,1,5\]의 n개 prefix. pair(0,1)는 모든 n, control pair(1,4)는 n≥5이다.
- 4 measurement settings cos_a/sin_a/cos_b/sin_b, 각 pair에서 exhaustive 2^(n−2) contexts.
- retained count entry와 histogram 합은 설정당 2048 shots. object header shots_per_circuit, 마지막-R8 config와 job metadata는 256 shots.
- 18개 η3/n model YAML 중 해당 6개의 현재 보존 바이트 SHA256과 backend snapshot SHA256이 원 execution metadata의 값과 정확히 일치한다.

## 관측·확인한 내용

- 누적 count entry 476개, pair/context 조합 119개, histogram 측정 합974,848 shots를 보존한다. 모든 선언된 pair/context/4-setting 조합이 있고 entry shots와 histogram 합이 일치한다.
- 보존된 6개 RR_R8 metadata와 6개 job ID는 exit_code=0, errors=\[\], dropped_contexts=\[\]이고 기록된 noiseless validation이 통과했다. 이는 이 최종 subrun 기록의 상태다.
- metadata는 frozen transpiled circuit cache 재사용을 기록한다. 정확한 QPY/cache manifest 파일 자체는 현재 저장소에 없다.
- 이번 정리의 raw-count 산술 점추정(n=7, bootstrap·필터 없음): pair(0, 1) V_circ=0.0003322794182, pair(1, 4) V_circ=0.0002281464328. 과거 figure의 bootstrap-median 결과로 표시하지 않는다.

## 해석

η3·날짜별 누적 counts는 실제 관찰 자산이고 마지막-R8 metadata는 그 일부 실행의 근거다. 재분석할 때 명시적 η3/run 선택과 effective 2048-shot histogram을 사용하고, 누적 실행의 모든 단계가 검증됐다고 확대하지 않는다.

## 한계와 미확인 사항

- 2048/256=8은 누적과 부합하지만 선행 R1–R7 metadata 및 전체 count-merge manifest가 보존돼 있지 않다. 누락된 실행 ID·job·시각·상태를 만들어 넣지 않는다.
- 정확한 model YAML와 backend snapshot 확인은 runtime runner commit, dirty state, transpiled QPY 동일성을 증명하지 않는다.
- 현재 README의 Day 1/2 선택과 원 timestamp를 구분한다. 원 run label에 들어간 숫자 시각을 metadata start_time의 대용으로 사용하지 않는다.
- 현재 Fig.5/6 recipe와 원 counts는 과거 figure 출력·승인·독립 감사 기록을 대신하지 않는다. 본 정리는 QPU를 재실행하지 않았다.
- 두 저장소의 동일 counts·metadata 사본은 독립 반복이 아니다. 별도 날짜의 다른 wrapper는 별도 관찰 묶음이다.
