## 질문

동일한 η3=0·n=7·mapping에서 측정 setting을 시간상 묶거나 interleave하는 schedule의 차이가 κ-profile과 측정 품질에 어떻게 나타나는가? 현재 Fig.7 recipe에서 재구성한 질문이다.

## 이유

현재 Fig.7 코드와 README는 blocked/interleaved schedule 비교를 목적으로 한다. 원 metadata에는 실행 조건·순서가 남지만 사전 설계나 인과적 판정 기준의 일지는 없다.

## 시도·변경

서로 다른4 execution ID로 interleaved512-shot 측정을 반복했다. 같은 configuration·model/cache를 사용하지만 raw counts와 job ID는 각 실행별로 보존한다.

## 조건

- η3=0, n=7, IBM Fez; physical qubits \[3,16,2,4,23,1,5\], pairs(0,1),(1,4), pair별 32 exhaustive contexts.
- 원 timestamp는 2026-01-02 UTC, 한국시간 2026-01-03. 시간 순서는 I1→I2→B→I3→I4이다.
- 원 model YAML SHA256=4359ff532c5445e09587c521451fd316fc59d0713dfef622f120378fd9600a58, snapshot SHA256=9a36cbca831059af718f6b267577abfe49c4ec30a2b3c0fd81c1c69e341b5881이며 현재 보존 바이트와 일치한다.
- frozen transpiled circuit cache key=13552e1015b260de267221ab08c1f4beaf05152b757d4b41b688cdf1433dedb0를 재사용했다고 기록한다.
- blocked는 설정당 2048 shots의 4 job; interleaved 각 구간은 설정당 512 shots의 1 job이다.

## 관측·확인한 내용

- I1–I4: 서로 다른 4개의 run_id와 4개 job ID, 각 num_rows=64·count entry 256개·131,072 shots. 네 구간 합계 1,024 entries·524,288 shots.
- 모든 보존 count의 shots와 histogram 합이 같고, 두 pair·32 context·4 setting 조합이 완전하다.
- 보존 metadata는 exit_code=0, errors=\[\], dropped_contexts=\[\]이며 validation passed=true다. exhaustive 때문에 context.samples를 무시했다는 경고와 cache 재사용 경고는 오류와 구분한다.
- 2026-11-10 기존 Fig.7 코드로 재생성한 총 2,048-shot 자료의 raw V_circ 점추정: (0,1): B=0.0003622917657, I_sum=0.0003898434246; (1,4): B=0.0003135986044, I_sum=0.0001980285432. CSV의 V_circ_point는 별도 bootstrap-median 값이다. 과거 원 figure 출력이나 새 획득 결과로 표시하지 않는다.

## 해석

schedule과 시간·shot budget을 구분한 원 counts 비교에 재사용할 수 있다. 총 shot 수를 맞춘 2048-shot 비교에는 interleaved 4구간의 합산이 필요하며, I_sum은 별도 획득이 아니다. 관찰된 차이의 인과적 원인이나 일반적 우월성은 별도 분석·설계로 평가한다. 이번 재생성의 raw 점추정에서는 pair별 B/I_sum 크기 순서가 다르다. 이 비교로 측정 순서의 일괄 우월성이나 차이의 유의성을 결론내리지 않는다.

## 한계와 미확인 사항

- blocked 하나와 512-shot interleaved 하나를 같은 shot budget으로 간주하지 않는다. I_sum의 분석 recipe는 현재 코드에 있지만 과거 생성 출력은 별도 보존돼 있지 않다.
- I1, I2와 I3, I4가 B 전후에 있으므로 순수한 schedule 효과와 시간 변화의 인과적 분리를 자동으로 주장하지 않는다.
- runtime code commit/dirty state와 실제 transpiled QPY/cache manifest는 보존되지 않았다. model/snapshot hash 일치는 그 파일들에 한정한다.
- 이 보존 묶음에서 실행 오류는 보고되지 않았다. 실패한 다른 시도가 없었다거나 전체 탐색을 보존했다고 일반화하지 않는다.
- 두 저장소에 동일한 원 counts가 있으므로 저장소 수를 반복 횟수로 세지 않는다.
